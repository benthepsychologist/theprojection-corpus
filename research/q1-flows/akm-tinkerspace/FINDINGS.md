# AKM migration experiment — findings

**What this is:** per `INBOX/2026-08-27-pm-q1-akm-migration-experiment.md`, this is an
ungoverned tinkerspace migration of `research/q1-flows/{nodes,edges,memberships}.yaml`
(theprojection-corpus's hand-curated, citation-backed AI-buildout money-flow graph —
204 entity/event nodes, 86 quantified flow edges, 118 investor/lender roster rows as of
this run) into the AKM/OKG shapes lifeos-registry landed 2026-08-26 (`3fe27e0`). The
migrated copy lives in this directory as five JSONL files (`atoms.jsonl`, `sources.jsonl`,
`relationships.jsonl`, `annotations.jsonl`, `extraction_passes.jsonl`), generated by
`migrate.py`, which is deterministic and idempotent — re-run it any time the YAML
register changes and it reproduces the same shapes from the new data. **The YAML
register stays authoritative; nothing reads this tinkerspace copy in production.**

The findings below are the actual deliverable pm's brief asked for — they're evidence
for cloud-governor's pending ruling on the round-two brief
(`/workspace/.projections/cloud-governor/INBOX/2026-08-27-pm-akm-round-two/BRIEF.md`),
not a proposal to adopt AKM for Q1.

## What mapped cleanly — no surprises

- **`about` / `member_of` / `funds`** (all three proposed, none landed yet — used as-if
  per pm's own instruction) behaved exactly as pm's mapping predicted. 180 `about`
  relationships (every claim linked to both its from- and to-entity), 118 `member_of`
  relationships (every membership row migrated 1:1, `role`/`amount_usd` riding in
  `qualifiers`), 86 `funds` relationships (one per edge, materialized from that edge's
  current claim, not evidence-bearing itself as the brief specified).
- **The `sources[]` field really is unnecessary.** Every edge's multiple observations
  became multiple separate `supports` relationships pointing at the same claim, with no
  list-shaped field anywhere doing the work `observations: [...]` does today. Multiplicity
  genuinely does live in the relationship count, as pm's Ask 5 predicted.
- **`coverage_state` has no governed home — confirmed empirically, not just asserted.**
  Every one of the 173 entity atoms' `coverage_state` (155 measured, 10 aggregated, 8
  unmeasured) sits in free-form `meta`, unvalidated and unqueryable by any trait. This
  run is a live second data point for the round-two brief's Ask 2 ruling request.

## What broke, with real numbers — four findings

### 1. "Different amounts on one edge" is not one phenomenon — and the naive read is wrong 100% of the time

The most important finding. Four edges in the current register carry more than one
distinct dollar amount across their observations. A first pass at this script treated
all four as revision sequences and linked them with `supersedes`, marking the earlier
figure `deprecated`. **Checking the actual note text against each case shows zero of
the four are a real revision:**

| edge | amounts | what it actually is | correct predicate |
| --- | --- | --- | --- |
| Amazon→Anthropic 2024-11 | $4B, $8B | a November tranche + the cumulative total across two tranches | `has_part` (whole→part) |
| Crusoe Abilene phase 2 | $11.6B, $15B | a phase-2 tranche + the cumulative total including phase 1 | `has_part` |
| Broadcom Anthropic SPV | $80B, $100B | two sources genuinely disagree on one still-forming facility's ceiling | `conflicts_with` |
| nVent/Maverick Power | $1.75B, $550M | a firm purchase price + a *separate*, contingent earnout | `qualifies` |

AKM already has landed predicates for exactly these three distinct relations
(`has_part`/`part_of`, `conflicts_with`, `qualifies` — all in the existing 30 seeds,
no proposal needed). The problem isn't AKM's vocabulary; it's that **Q1's flat
`observations: [...]` list gives no structural signal for which of these three
situations a second amount represents — you have to read the prose every time.**
`migrate.py`'s `classify_multi_amount()` does this by keyword-matching the note text
("cumulative total" → `has_part`, "earnout"/"contingent" → `qualifies`, else
`conflicts_with`) and is explicitly a heuristic, not a solved parser — every
classification it makes is flagged `review_status: unreviewed` with a note saying so.
**The finding isn't "the classifier works," it's "today's schema can't tell these
apart without a human or an agent reading every multi-observation edge's prose,"**
which is real, uncosted work if Q1 (or any future AKM-native corpus) wants this
distinction made reliably at write-time instead of reconstructed later.

### 2. Claim atoms are supposed to be self-contained prose; Q1's `note` field is a fragment meant to be read beside its edge

An AKM claim's canonical example (round-two brief) is a full sentence: *"TSMC
committed $12B to its Arizona fab, 2021–2029."* Q1's actual stored note for that exact
edge is `"$12B, 2021-2029"` — true, but meaningless without also knowing the edge's
`from`/`to`. This isn't a data-quality bug in Q1; its schema was designed so the
*edge* carries the who-paid-whom and the *observation* carries only the amount/date,
because the entity×activity node split already encodes the parties. Flattened into a
standalone AKM claim atom, that context has to be re-synthesized. `migrate.py` does
this mechanically (`"{from label} → {to label}: {note}"`), which works but produces
awkward sentences, not real prose (`"TSMC (foundry construction) → TSMC (advanced
packaging construction): additional $100B; brings total US commitment to ~$165B"`).
**If Q1-shaped data is ever authored AKM-native, claims need to be written as real
sentences at capture time — a real workflow change, not a migration-script fix.**

### 3. Bare entity labels destroy Q1's own core design principle — 38 collisions found, fixed, but only by hand

Q1's foundational rule (its own README, restated in every pass) is that a company's
capital-raising facet is a *different node* from its construction facet specifically
so they don't get conflated. `knowledge_atom.label` has no first-class "activity"
field to carry that distinction — using the bare `entity`/`company` string produced
**38 labels shared across multiple genuinely distinct nodes** on the first migration
run, worst case `"ext (population)"` covering *six unrelated* undisclosed-investor
placeholder nodes with nothing to tell them apart. Appending the activity/round-type
to the label (`"CoreWeave (datacenter operation)"` vs. `"CoreWeave (capital)"`) fixed
all 38 in this script — but that's this script's own repair, not something the target
schema does for free. Any future consumer of AKM-shaped entity atoms needs the same
fix applied, or the collisions come back.

### 4. Two integrity gaps flagged, deliberately NOT papered over

- **`provenance_class: "inference from other claims"` doesn't fit `source` at all.**
  Four sources in this migration have this provenance class, and their actual content
  is things like a bare `"n/a"` figure — because they're not external evidential
  artifacts, they're **Q1's own derived reasoning** (a sum of two other tracked
  claims, an inferred allocation). Forcing these into `source.evidence_class` (this
  script uses `absence_of_evidence` as the least-wrong fit) mischaracterizes them as
  weak external evidence when they're actually strong *internal* derivations. The
  landed `derived_from` predicate (claim→claim) is very likely the right home instead
  — not attempted in this pass since it would mean re-deriving which specific claims
  each inference actually summed, which the current YAML doesn't record structurally.
- **Every `extraction_pass.source_target_ref` in this migration is a placeholder
  (`source:unspecified`) that resolves to nothing in `sources.jsonl`.** The schema
  requires exactly one source per extraction pass; Q1's `capture_ref` values (e.g.
  `session-webfetch:2026-08-12`) are session-level markers that can cover many
  sources fetched in one sitting. This is the mirror image of P-01 (a field forced
  single-value against a genuinely-multiple reality) — except this time it's AKM's
  own schema doing the forcing, on the receiving end of the exact principle Q1
  invented for itself. Left broken and documented rather than silently patched with a
  fake reference, because the real fix is a design decision (does `extraction_pass`
  need a `source_target_refs` list, or does Q1 need to record capture at
  per-source granularity going forward?) that isn't this script's to make.

## What this means for the round-two brief

- **Ask 2 (coverage_state ruling):** this run is a second real consumer confirming
  the gap is real, not hypothetical — worth citing as evidence either way it's ruled.
- **Ask 5 (the factoring note):** confirmed correct for the common case; the four
  multi-amount edges above are the caveat worth adding — the factoring holds, but
  "one edge, N observations" sometimes needs `has_part`/`qualifies`/`conflicts_with`
  between claims, not just N `supports` relationships into one claim.
- **New, not in either brief:** the extraction_pass cardinality mismatch (finding 4)
  and the label-collision gap (finding 3) are genuinely new findings this experiment
  surfaced that neither pm's mapping nor the round-two brief's five asks anticipated.

## Reproducing this

```
cd research/q1-flows/akm-tinkerspace
python3 migrate.py
```

Reads the current `../{nodes,edges,memberships}.yaml`, writes the five JSONL files in
this directory, and prints a reconciliation tally. Safe to re-run after any future
q1-flows research pass; nothing here is hand-edited.
